All notable changes are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions with `b`/`rc` are
pre-releases and **not** a recommendation for production use.

## [Unreleased]

## [0.5.0b4] - 2026-11-03

Experimental beta maintenance release. Independent validation on a separate development VM passed (181 router, 216 HA integration tests; focused ASM regressions, lint and public audit). The fix has not yet been validated on a real Home Assistant system. No device-control permissions or service calls are added. `v0.5.0b3` remains the previous beta for rollback.

### Fixed
- **ASM learning confirmation:** the open learning question was consumed *before* the
  ChatLog context was checked, so a „Ja“ in a wrong or incomplete context destroyed it
  (reported with v0.5.0b3: „Ja“ → „Das habe ich nicht verstanden.“, lexicon stayed empty).
  The proposal is now only read first and consumed once the turn right before the answer
  is this agent's own learning question (both quoted words must appear in it) **and** the
  answer is an explicit yes or no. Any other reply lets it lapse, an invalid context leaves
  it untouched until it expires. The 60-second window is unchanged. Nothing about the
  spoken text is stored or logged; the outcome is logged as a code only
  (`asm_confirmation=stored|declined|unconfirmed|expired|context_invalid|not_stored`,
  debug level).

## [0.5.0b3] - 2026-11-01

Experimental beta pre-release published with Owner approval. Includes ASM and safe short conversational follow-ups; independently tested on a separate development VM (179 router/static + 203 integration tests, Ruff, public audit). GitHub CI passed. Real Home Assistant / STT validation is not yet completed; use with backup and rollback, not for safety-critical control.

### Added
- **Adaptive Speech Memory** (optional, off by default, mode Active only): after a
  correction such as „Nein, ich meinte Mulan“ the original request is answered with the
  corrected word and Nabu asks once whether to remember the pair. Only an explicit „Ja“ in
  the same conversation within 60 seconds stores it; confirmed pairs are then applied to
  harmless conversation. Device, room, control, status and confirmation words are never
  learned or replaced; commands and status requests are never rewritten.
- Options page *Speech memory*: switch, overview, add, edit, delete, reset with
  confirmation (German and English).
- Local persistence with Home Assistant `Store` (versioned, atomic, private, 200 entries);
  unreadable or invalid data is locked and left untouched until an explicit reset.
- Diagnostics report only the switch state, storage state and number of entries.

### Changed
- One shared, single-use 60-second window for open dialogue states (follow-up question,
  learning proposal, router clarification); a new question replaces the old one.
- After an unclear one-letter reply („T.“) Nabu repeats the short question from Home
  Assistant's chat log („… Kaffee oder Tee?“) instead of a generic request.
- A reply ending with „;“ no longer counts as a question.

### Fixed
- In Active mode, a short answer to an actual prior conversational question now reaches
  Hermes with the existing Home Assistant chat history instead of being treated as a new
  device fragment. A 60-second, one-time, per-session window stores no message text.
- Single-character STT results such as `T.` are not guessed; Nabu asks for repetition.
- Device-related replies, new commands, standalone fragments, and the Off/Observe modes
  retain their previous security behavior. No direct HA device actions are added.

### Limitations
- This work does not repair STT transcriptions, stop multiple questions generated by
  Hermes in one reply, or implement HA device-action follow-ups.
- Published as an experimental beta after Owner approval. Live HAOS/STT/Echo acceptance and installation are still outstanding.

## [0.5.0b2] - 2026-10-30

Experimental beta maintenance release, verified through CI and workshop tests.
The Owner also confirmed the voice agent selection and a real HAOS conversation test.

### Fixed
- Normalize the Hermes Companion's wildcard language list `["*"]` into Home Assistant's
  required literal `"*"` for conversation agents. Without this normalization, the agent
  appears disabled in the voice pipeline language selector despite being connected.
- Add regressions for wildcard, mixed wildcard, explicit language lists and empty lists.

## [0.5.0b1] - 2026-10-30

First standalone version, published as an experimental pre-release with no warranty.

### Added
- Own Home Assistant conversation agent (`conversation.kinetic_voice_router`); no patch or
  coupling to the `hermes_agent` integration is needed any more.
- Setup, re-authentication and reconfiguration of the Hermes Agent Companion in the UI:
  URL, bearer token, optional TLS-check switch, real connection test (`/health`,
  `/v1/capabilities` API major 1, conversation offered) before anything is saved.
- "Hermes connection" page in the options with a live probe and honest status
  (reachable / token rejected / incompatible API / no conversation / unreachable).
- Minimal Hermes client with redirect refusal, URL safety checks, size and time limits,
  and redacted errors.
- Operating modes Off / Observe / Active (default Off) with the router policy of 0.4.x.
- Public package structure for HACS (`hacs.json`, one integration), `NOTICE`, `SECURITY.md`,
  CI (tests on Python 3.11 and 3.13, lint, `hassfest`, HACS validation, public-tree audit).

### Changed
- The router no longer publishes itself in `hass.data`; the old "bridge API 2" is gone.
- Entry version is now 1.3. Entries from 0.4.x keep their chosen mode; because they hold no
  Hermes connection, Home Assistant asks for URL and token (re-authentication) after the update.
- Diagnostics no longer contain anything about the Hermes URL or token, only whether they exist.

### Carried over from the 0.4.x line (router behaviour)
- Statements about unknown own devices ("Is my ... switched on?") get the honest status answer.
- Explanations are no longer blocked by the answer filter when Hermes honestly states a
  channel limit; the remainder of such a sentence is still checked strictly.
- Fail-closed behaviour on internal router errors in Active mode; reset of counters only
  after explicit confirmation; abbreviations and list numbers no longer end a spoken sentence.

### Not included / open before a first release
- No brand icon: origin and licence of the icon used in the private line must be confirmed.
- No real Home Assistant, HACS or hardware test has been run for this version.
- Release workflow exists but no tag or release has been created.
